# Plan and Handover Structure

Plans and handovers use these sections, in order. Keep each short; if a section does not apply, say so in one line.

1. **Problem:** expected versus actual behavior, reproduction, and evidence.
2. **Solution:** the chosen approach, alternatives considered, and why this one fits the problem.
3. **Product behavior:** what users see and do, before and after.
4. **Technical approach:** how it works: data, interfaces, and dependencies.
5. **Code structure:** a Mermaid flowchart or pseudocode of the main flow.
6. **Edge cases:** each case and whether it is handled, deferred, or left unsupported.
7. **Verification:** how the problem is reproduced and how the fix is proven.
